Version:      2.0
Status:       Specification draft (not yet silicon-verified)
Architecture: SIMT (Single Instruction, Multiple Threads)
Execution:    Warp-based, 32 lanes per warp
Encoding:     64-bit fixed width, little-endian
Implementations: Software VM (reg-10/kernel/usermodedriver), FPGA target TBD

================================================================================
1. MACHINE MODEL
================================================================================

Registers
----------

  r0      Zero register (reads 0, writes ignored), per-lane            [IMPLEMENTED+TESTED]
  r1-r31  General-purpose 32-bit integer registers, per-lane           [IMPLEMENTED+TESTED]
  f0-f31  Floating-point registers, per-lane, IEEE 754 binary32        [IMPLEMENTED+TESTED]
  p0-p7   Predicate registers, per-lane, 1 bit each                    [IMPLEMENTED+TESTED]
  pc      Program counter, per-warp, byte-addressed                    [IMPLEMENTED+TESTED]
  laneid  Lane index 0-31, per-lane, read-only via LANEID              [IMPLEMENTED+TESTED]

Predicate register note: p0-p7 are the ONLY architecturally visible
predicate registers. The 4-bit pd field in SETP/NOTP encodes P0-P15,
but values 8-15 are reserved and cause an illegal-operand fault in the
VM. The hardware may expand to 16 predicates in v3; v2 software must
not use pd >= 8.

Warp state
----------

  Each warp executes in lockstep across all active lanes.
  Active lanes are tracked by a 32-bit active_mask.
  Inactive lanes (masked off by divergence or the initial launch)
  do not execute; their registers are not modified.
  Maximum warps per core: 32 (REG10_NUM_WARPS_PER_CORE).

Memory spaces
-------------

  Global RAM     Shared across all cores. LDG/STG address this.
                   Size: 64 MiB (REG10_GLOBAL_RAM_SIZE).
  Scratchpad     Per-core, software-managed. LDS/STS address this.
                   Size: 64 KiB per core (REG10_SCRATCHPAD_SIZE).
                   Addresses wrap modulo scratchpad size (architectural
                   behaviour, not a bug; see section 7).
  No caches. No hardware coherence. The kernel is responsible for
  ordering; see section 8 (Memory Model) for fence semantics.
